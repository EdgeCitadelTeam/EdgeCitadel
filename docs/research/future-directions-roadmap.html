Implementation Gap Plan

Close the repo gap by turning manual baseline commands into a reproducible harness before adding new architecture modes.

What exists now

  • NativeFastAPI command endpoint publishes canonical envelopes to `agents.{id}.inbox` with `Nats-Msg-Id`.
  • DurableJetStream work queue, explicit ack, per-agent durable consumers, and duplicate-window dedupe are implemented.
  • StreamAdapters can emit `task.progress`; final `result` remains canonical and auditable.
  • FailureWatchdog handles heartbeat staleness and MAX_DELIVERIES advisory paths for offline recipients.
  • Memory`memory.turns.*` and conversation tables exist for context replay experiments.

What to build next

  • HarnessCreate `scripts/research/run_agent_benchmark.py` with workload plugins, JSON output, and repeatable trial control.
  • FixturesAdd test agents for crash-before-ack, side-effect counters, simulated L2 delegation, and synthetic MQTT ingress.
  • MetricsCapture origin publish, first progress, final result, queue depth, poison events, duplicates, CPU, and memory.
  • RendererGenerate Markdown/HTML result summaries from JSON so the paper tables stay reproducible.
  • GatesBack the harness with unit tests plus the existing stack smoke and Playwright workflow gate.

Build Runway

Sequence matters: stabilize native results first, then add harder failure modes, then compare MQTT and semantic extensions.

Phase 0 Freeze the claim ladder

Lock paper claims before adding features. Each experiment must answer a named claim, especially C2, C4, and C5 from the research plan.

Phase 1 Automate E1, E4, E5, E7

Convert current manual baselines into repeatable trials with fixed prompts, task IDs, polling rules, and JSON result files.

Phase 2 Add E6 crash and E15 replay safety

Use a disposable consumer and harmless counter side effect to measure redelivery without risking real tools.

Phase 3 Add MQTT ingress mode

Enable MQTT only as ingress. Record pre-normalization MQTT payloads and post-normalization canonical envelopes.

Phase 4 Measure semantic failures

Add clarification, verification, provenance, and replay-policy probes as envelope extensions or sidecar annotations.

Experiment Setup

The setup should produce reproducible figures and falsifiable claims, not only a successful demo.

  1. Start the stack with `docker compose up --build -d`; start `shell-1`, `gemma-1`, and `watchdog-1` as host adapters.
  2. Verify health through `/api/system/status`, `/api/registry`, `/api/messages`, and `/api/poison` before any trials.
  3. Run one warmup per workload, then run fixed trial counts with unique `task_id` and controlled `context_id` rules.
  4. Persist one JSON object per trial plus a summary JSON file containing p50, p95, p99, duplicate counts, poison events, CPU, and memory.
  5. Render paper-ready tables into `docs/research/results/` and link them back to the experiment matrix.
Native control

Measure E1, E4, E5, and E7 first. This creates the control group for every later MQTT, gateway, and semantic-layer comparison.

Failure probes

Use crash-before-ack and non-idempotent side-effect counters to show where transport replay helps and where semantics must intervene.

MQTT ingress

Introduce MQTT only after the native baseline. Compare relay complexity, latency overhead, auth surface, and normalization ambiguity.

Semantic probes

Score stale context, wrong delegation target, unverifiable answer, missing provenance, and unsafe replay as `semantic_failures`.

Recommended Paper Bet

Make the benchmark suite the primary future direction, use the semantic layer as the paper's intellectual boundary, and use MQTT ingress as the controlled comparison that validates the architecture split.
