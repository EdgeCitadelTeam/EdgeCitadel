# EdgeCitadel Agent Contract (v0.1)

**Status:** Authoritative for v0.1. Aligned with the A2A v1.0 task lifecycle vocabulary; NATS JetStream is the only transport. The legacy informal envelope (with `receiver_id`, `message_type`, `content`, `from`, `to`, `correlation_id`, `causation_id`, `chain_id`, `assigned_agent`) is removed without alias-fallback. See [ADR-0003](adr/0003-a2a-v1-vocabulary-adoption.md).

This document is the single source of truth for what it means to be an agent on EdgeCitadel. Any runtime — AG2, LangGraph, a raw Python script, an ESP32 firmware, a Mac mini running Gemma — that satisfies this contract can join the mesh and interoperate with every other agent.

The contract has three layers. They are independent but must all be implemented for conformance:

1. **Envelope** — the wire format of a single message (§1).
2. **Lifecycle** — the subjects an agent must publish and subscribe to, and the order in which it must do so (§2).
3. **Agent Card** — the self-description an agent publishes at registration so peers know how to address it (§3).

Transport in v0.1 is NATS JetStream. The Agent Card declares the binding via the EdgeCitadel-private A2A extension URI `https://edgecitadel.local/ext/nats-binding/v1` (see §3). HTTP+SSE A2A interop is deferred to Phase 4 via the `A2aAgentServer` wrapper.

## 1. Envelope

Every message published to an `agents.*`, `tasks.*`, or `system.*` subject MUST be a JSON object that validates against [`schemas/envelope.v1.json`](../schemas/envelope.v1.json). The schema is **strict**: it rejects unknown top-level fields. Producers MUST emit only the canonical names below.

### 1.1 Field reference

| Field | Type | Description |
|---|---|---|
| `v` | integer (`1`) | Envelope version. v0.1 = `1`. |
| `id` | string (UUID4) | Unique message ID. Used for idempotency / `Nats-Msg-Id` header. |
| `type` | string (enum) | Envelope type. See §1.2. |
| `sender_id` | string | Publisher's agent ID. Pattern: `^[a-z0-9][a-z0-9_-]{0,63}$`. |
| `recipient_id` | string | Addressee's agent ID. Required for `command`, `result`, `delegation`, `cancel`. |
| `timestamp` | string | ISO 8601 UTC with ms precision and `Z` suffix, e.g., `2026-04-23T10:00:00.000Z`. |
| `task_id` | string (UUID4) | A2A task ID. Generated by the originator; echoed unchanged by responders. New `task_id` per delegation hop (child task ≠ parent task) — use `context_id` to group hops. Required for `command`, `result`, `delegation`, `cancel`, `task.progress`. |
| `context_id` | string (UUID4) | A2A context ID; shared across a delegation chain. Required on `delegation`; SHOULD propagate on related `result`, `task.progress`, `cancel` envelopes. |
| `task_state` | string (enum) | A2A task lifecycle state. Required on `result` and `task.progress`. MUST NOT appear on `register`, `heartbeat`, `log`, `broadcast`, or `status`. See §1.3. |
| `agent_state` | string (enum) | EdgeCitadel agent-runtime state. Present only on `status`. MUST NOT appear on any other envelope type. See §1.4. |
| `hop_count` | integer (≥0) | Delegation depth: 0 at root, +1 per hop. Required on `delegation`. Adapters MUST refuse delegation when `hop_count >= 8`. |
| `payload` | object | Type-specific body. Always an object (possibly empty). See §1.5. |

### 1.2 `type` enum (10 values)

| `type` | Direction | Subject | Persistence |
|---|---|---|---|
| `register` | agent → fleet | `agents.{self}.register` | Plain NATS + aggregator cache |
| `heartbeat` | agent → fleet | `agents.{self}.heartbeat` | Plain NATS (ephemeral) |
| `status` | agent → fleet | `agents.{self}.status` | Plain NATS (ephemeral) |
| `command` | sender → recipient | `agents.{recipient}.inbox` | JetStream `AGENT_INBOX` |
| `result` | responder → requester | `agents.{requester}.inbox` | JetStream `AGENT_INBOX` |
| `delegation` | agent → agent | `agents.{recipient}.inbox` | JetStream `AGENT_INBOX` |
| `cancel` | sender → recipient | `agents.{recipient}.inbox` | JetStream `AGENT_INBOX` |
| `log` | agent → fleet | `agents.{self}.log` | Plain NATS (ephemeral); persisted by aggregator |
| `broadcast` | any → all | `system.broadcast` | Plain NATS (ephemeral) |
| `task.progress` | agent → observers | `agents.{self}.task_progress.{task_id}` | Plain NATS (ephemeral) |

Note the dual naming convention: NATS subjects use underscores within segments (`task_progress`), but envelope `type` values follow A2A dotted convention (`task.progress`). This is intentional and not a bug.

### 1.3 `task_state` enum (A2A v1.0, 8 values)

| Value | Semantics |
|---|---|
| `submitted` | Task accepted but not yet started. |
| `working` | Task is executing. Progress updates use this on `task.progress`. |
| `input-required` | Task is paused waiting for additional input from the sender. |
| `auth-required` | Task is paused waiting for authentication or authorization. |
| `completed` | Terminal: task finished successfully. |
| `failed` | Terminal: task failed. Failure detail in `payload.error`. |
| `canceled` | Terminal: task was canceled before completion. |
| `rejected` | Terminal: task was refused (e.g., `hop_count >= 8`, busy, unknown agent). |

Terminal states: `completed`, `failed`, `canceled`, `rejected`. Intermediate progress uses `type: task.progress` with `task_state: working` (or `input-required` / `auth-required`).

`task_state` MUST NOT appear on `register`, `heartbeat`, `log`, `broadcast`, or `status` envelopes — it is exclusively a task-lifecycle field.

### 1.4 `agent_state` enum (4 values)

| Value | Meaning |
|---|---|
| `online` | Agent is connected and ready to accept work. |
| `offline` | Agent is shutting down or has shut down cleanly. |
| `busy` | Agent is connected but currently rejecting work (or only accepting a narrow set). |
| `error` | Agent is connected but in a self-declared error state; observers may still send (recovery is expected). |

`agent_state` is present only on envelopes with `type: status`. It MUST NOT appear on any other envelope type (`register`, `heartbeat`, `command`, `result`, `delegation`, `cancel`, `log`, `broadcast`, `task.progress`). Task lifecycle state (`task_state`) and agent runtime state (`agent_state`) are deliberately separate enums to avoid collision.

### 1.5 Payload conventions

`payload` is a type-agnostic object. The schema does not constrain its shape in v0.1; conventional fields are:

| Field | Present in | Semantics |
|---|---|---|
| `body` | `command`, `result`, `delegation`, `broadcast`, `log` | Human-readable text (prompt, reply, log message). |
| `args` | `command`, `delegation` (optional) | Structured arguments object, agent-specific schema. |
| `error` | `result` when `task_state ∈ {failed, rejected}` | Short machine-readable error tag. |
| `reason` | `cancel`, `status` (optional) | Human-readable reason string. |
| `progress` | `task.progress` (optional) | Integer 0–100 for known-fraction work. |
| `message` | `task.progress` (optional) | Human-readable progress description. |
| `task_id` | `cancel` (required) | Task to cancel. Echoed in top-level `task_id` for routing. |
| `level`, `context` | `log` | `level ∈ {debug, info, warn, error}`; `context` is an arbitrary structured object. |
| `cpu_percent`, `memory_percent`, `power_source`, `battery_percent` | `heartbeat` (all optional) | Informational telemetry. |

Unknown payload fields are preserved through the aggregator DB but not interpreted.

### 1.6 Required-by-type matrix

| `type` | Required top-level fields (in addition to baseline `v`/`id`/`type`/`sender_id`/`timestamp`/`payload`) |
|---|---|
| `register` | — |
| `heartbeat` | — |
| `status` | `agent_state` (must NOT carry `task_state`) |
| `command` | `recipient_id`, `task_id` |
| `result` | `recipient_id`, `task_id`, `task_state` |
| `delegation` | `recipient_id`, `task_id`, `context_id`, `hop_count` |
| `cancel` | `recipient_id`, `task_id` |
| `log` | — |
| `broadcast` | — |
| `task.progress` | `task_id`, `task_state` |

### 1.7 Sender identity

`sender_id` is self-declared and therefore untrusted until bound to transport-layer authentication. Until per-agent auth ships (v0.2):

- A receiver (peer or aggregator) MUST reject any envelope whose `sender_id` does not match a currently-cached Agent Card. No card → no identity → drop and log.
- For `register` envelopes specifically: `sender_id` MUST equal the Agent Card payload's declared identity. A mismatch is rejected.
- Receivers SHOULD log — not silently drop — rejected envelopes.

### 1.8 Size and encoding

- UTF-8, no BOM.
- Hard limit: 1 MB per envelope (NATS default; enforced by the broker).
- Bodies above ~256 KB SHOULD use `payload.body_ref` pointing at a JetStream object-store entry instead of inlining.

## 2. Lifecycle

Every agent is a state machine over the four `agent_state` values: `online`, `offline`, `busy`, `error`. Transitions are observable via `type: status` envelopes.

### 2.1 Subject inventory

| Subject | Published by | Consumed by | Persistence | Envelope `type` |
|---|---|---|---|---|
| `agents.{id}.register` | Agent (self) | Aggregator (plain sub) | Plain NATS + aggregator cache | `register` |
| `agents.{id}.heartbeat` | Agent (self) | Watchdog + aggregator | Plain NATS | `heartbeat` |
| `agents.{id}.status` | Agent (self) | Watchdog + aggregator | Plain NATS | `status` |
| `agents.{id}.log` | Agent (self) | Aggregator | Plain NATS | `log` |
| `agents.{id}.inbox` | Any sender | Agent's durable JetStream consumer | **JetStream `AGENT_INBOX`** | `command`, `result`, `delegation`, `cancel` |
| `agents.{id}.task_progress.{task_id}` | Agent processing the task | Aggregator + Phase 4 SSE bridge | Plain NATS | `task.progress` |
| `agents.{id}.outbox` | Agent (self) | Aggregator (audit) | Plain NATS | Mirror of what `{id}` is sending |
| `agents.watchdog-1.outbox` | Watchdog | Aggregator | Plain NATS | `status: offline` notices about other agents (non-impersonating) |
| `system.broadcast` | Any | All agents | Plain NATS | `broadcast` |
| `tasks.{task_id}.{event}` | Aggregator | Dashboard (WS) | Plain NATS | Task board events |
| `$JS.EVENT.ADVISORY.CONSUMER.MAX_DELIVERIES.AGENT_INBOX.>` | JetStream (internal) | Aggregator | Plain NATS | Poison-message alerts |

**Routing rule:** only `agents.{id}.inbox` is persistent (JetStream `AGENT_INBOX`). Everything else is plain NATS fire-and-forget.

**Sender-side publish semantics:**

- For `command` / `delegation` / `cancel` / `result`: `js.publish("agents.{recipient}.inbox", env, headers={"Nats-Msg-Id": env["id"]})` for at-least-once + dedup.
- For everything else: plain `nc.publish(subject, env)`.
- Agents MUST publish to their own `outbox` mirror whenever they publish to another agent's inbox.

### 2.2 Required behavior

Every conformant agent MUST:

- **Publish** `register` exactly once per session, on connect, with the Agent Card as payload. Aggregator caches it; late subscribers fetch via `GET /api/agents` or trigger a `request_register` broadcast.
- **Publish** `heartbeat` at the interval declared in the Agent Card under `metadata["runtime.heartbeat_interval_sec"]` (default 30 s; range 10–300 s). Watchdog marks the agent offline after 3× the declared interval.
- **Publish** `status` when `agent_state` changes. Final envelope before clean shutdown SHOULD be `agent_state: offline, payload.reason: "shutdown"`.
- **Subscribe** durably to `agents.{self}.inbox`. Consumer name: `{agent_id}_inbox`, created idempotently (create-if-not-exists).
- **Subscribe** to `system.broadcast` unless the Agent Card declares `metadata["runtime.listens_broadcast"] = false`.
- **Refuse** `delegation` when `hop_count >= 8` by replying with `type: result, task_state: rejected, payload.error: "hop_limit"`.
- **Echo** `task_id` and `context_id` unchanged on every reply.

### 2.3 Watchdog role

A Watchdog (typically the aggregator, but it can be a peer):

- Subscribes to `agents.*.heartbeat` and `agents.*.status`.
- Tracks last-seen per agent, keyed by the `runtime.heartbeat_interval_sec` declared in that agent's cached card.
- When the threshold is exceeded, publishes a synthetic `status` envelope on `agents.watchdog-1.outbox` (NOT on the stale agent's subjects — the contract forbids impersonation):
  ```json
  {"sender_id": "watchdog-1", "type": "status",
   "agent_state": "offline",
   "payload": {"observed_agent_id": "{stale_id}", "trigger": "heartbeat_staleness"}}
  ```
- Clears the cached Agent Card so late subscribers don't see ghost peers.

Watchdog-role conformance is declared in the Agent Card via `metadata["runtime.roles"]` containing `"watchdog"`.

### Recipient offline

When agent A publishes `command` to `agents.B.inbox` and B is offline,
the watchdog (`agent_id: watchdog-1`) synthesises a `result` envelope
on A's behalf. The synthesised envelope carries
`task_state: failed, payload.error: "recipient_offline",
sender_id: watchdog-1`. Synthesised publishes share the dedup key
`Nats-Msg-Id: watchdog-syn-{task_id}` so JetStream's 5-min
`duplicate_window` collapses double-fires.

Three reinforcing trigger paths produce the synthesised envelope:

1. **Heartbeat-staleness fast path** (primary). When the watchdog has
   not seen a heartbeat from B for `max(2 × declared_interval, 20s) + 5s
   tolerance`, it fans out a synthesised failure for every in-flight
   task observed in B's outbox stream. ~30–65 s detection.
2. **Sticky-offline immediate path.** Once B is flagged offline, any new
   `command` or `delegation` observed on the outbox feed targeting B is
   synthesised immediately (~ms).
3. **MAX_DELIVERIES advisory backstop.** JetStream's
   `$JS.EVENT.ADVISORY.CONSUMER.MAX_DELIVERIES.AGENT_INBOX.>` advisory
   is the authoritative "this message will never deliver" signal. The
   watchdog synthesises in response to it for any task the fast paths
   missed (cold-start, watchdog restart gap, dropped outbox traffic).

Rationale and tradeoffs: see `docs/adr/0007-watchdog-trigger-model.md`.

### Skills

Adapters declare skills on their A2A Agent Card. Callers select a skill via `payload.skill_id` on `command` envelopes; missing → defaults to the agent's primary skill. Unknown `skill_id` → `task_state: rejected, payload.error: "unknown_skill"`.

Each skill in the card includes:
- `id` — fully-qualified identifier (e.g., `reasoning.chat`, `text.summarize`).
- `name`, `description`, `tags` — A2A v1.0 metadata.
- `system_prompt` — template prepended to inference (adapter-internal; not exposed via card).
- `defaults` — per-skill defaults (temperature, max_tokens, etc.).
- `output_shape` — `"free_text"` (default) or `{type: "json", schema: <JSON Schema>}`.

For `output_shape: json` skills, the adapter requests structured output from the underlying model (e.g., Ollama's `format: "json"`) and validates the response against the schema. Validation failure → `task_state: failed, payload.error: "structured_output_validation_failed", payload.raw: <model output>`.

The result envelope's `payload.skill_id` echoes the dispatched skill so audit/correlation works without consulting the original command.

### Streaming

Adapters that advertise `capabilities.streaming: true` may emit `task.progress` envelopes during inference. Phase 2.5 standard cadence: hybrid 8-tokens-or-100ms flush. Payload shape:

```json
{
  "type": "task.progress",
  "sender_id": "<agent_id>",
  "task_id": "<inbound task_id>",
  "task_state": "working",
  "payload": {
    "delta": "<accumulated chunk>",
    "skill_id": "<active skill>"
  }
}
```

`task.progress` is plain NATS (no JetStream durability) — frames may be dropped if a subscriber is slow. The canonical `result` envelope is the audit record; it always emits with the full text after streaming completes.

Cancel mid-stream: receiver publishes `result` with `task_state: canceled` and `payload.partial_body` carrying text accumulated to that point.

### Conversational memory

Adapters that need cross-turn memory request it from the aggregator's memory service via NATS request-reply on `memory.turns.{get,put,delete}`. The aggregator owns the `conversation_turns` table in `/data/openclaw.db`; adapters never read or write the DB directly.

- `memory.turns.get`: `{context_id, agent_id, token_budget?}` → `{turns: [...], total_tokens}`. Sliding-window eviction at the budget boundary.
- `memory.turns.put`: `{context_id, agent_id, role, content, skill_id?}` → `{id, token_count}`.
- `memory.turns.delete`: `{context_id}` → `{deleted_count}`.

Best-effort by design: a memory service timeout or failure returns empty/None — the adapter logs WARN and proceeds statelessly. Inference always succeeds.

Retention: hard-delete after 30 days of context idle. See ADR-0008 for architectural rationale and v0.3 semantic-memory forward hooks.

## 3. Agent Card

The Agent Card is the payload of the `register` envelope. v0.1 adopts the **A2A v1.0 Agent Card JSON shape** verbatim. Schema lives at [`schemas/agent-card.v1.json`](../schemas/agent-card.v1.json) (rewritten in Task 2; A2A v1.0 shape + EdgeCitadel metadata).

### 3.1 Mandatory A2A fields (v1.0)

`name`, `description`, `version`, `url`, `provider`, `capabilities`, `securitySchemes`.

### 3.2 Required by EdgeCitadel convention

`skills[]`, `defaultInputModes`, `defaultOutputModes`, `additionalInterfaces`, `capabilities.extensions`, `metadata`.

### 3.3 NATS transport binding

EdgeCitadel mints the URI `https://edgecitadel.local/ext/nats-binding/v1` and declares it on every Agent Card via A2A's documented extension mechanism:

```json
"capabilities": {
  "streaming": true,
  "extensions": [{
    "uri": "https://edgecitadel.local/ext/nats-binding/v1",
    "description": "NATS JetStream transport binding for EdgeCitadel fleet.",
    "required": false,
    "params": {"subject_prefix": "agents.{agent_id}"}
  }]
},
"additionalInterfaces": [
  {"url": "nats://edgecitadel/agents.{agent_id}.inbox", "transport": "nats-jsonrpc"}
]
```

This is a legitimate use of A2A's documented extension mechanism, not a deviation — A2A v1.0 explicitly supports custom bindings via `additionalInterfaces` and custom capabilities via extension URIs.

### 3.4 EdgeCitadel `metadata` vocabulary

| Key | Required | Values |
|---|---|---|
| `runtime.roles` | yes | Array of role strings: `worker`, `reasoner`, `watchdog`, `orchestrator` |
| `runtime.tags` | no | Free-form tags (model family, deployment, capabilities) |
| `runtime.deployment` | no | Deployment identifier, e.g., `mac-mini-studio-01` |
| `runtime.kind` | yes | `native` (speaks A2A/NATS directly), `bridge` (facade for an external runtime), or `gateway` (multiplexing surface like the MCP server or external A2A gateway; see §"A2A and MCP surfaces") |
| `runtime.conformance` | yes | `L1` (reachable), `L2` (collaborative — handles delegation, refuses at `hop_count >= 8`, propagates `context_id`), or `L3` (typed — A2A skill schemas + MCP). See §4. |
| `runtime.upstream` | required if `runtime.kind = bridge` | Identifier of the upstream runtime |
| `runtime.heartbeat_interval_sec` | no | Heartbeat interval (default 30 s; range 10–300 s) |
| `runtime.listens_broadcast` | no | Boolean; defaults to `true` |
| `runtime.chain_depth_limit` | no | Per-agent override of the default `hop_count >= 8` refusal threshold |

`runtime.kind` and `runtime.upstream` are informational — they do not change NATS routing but let operators and the aggregator reason about failure modes.

### 3.5 Card discovery

NATS core does not retain messages; the v0.1 discovery story is:

- Aggregator's `GET /api/agents/{id}/card` and `GET /api/agents` (list) serve cached cards.
- New clients call those HTTP endpoints on startup rather than relying on NATS retention.
- If the aggregator restarts, it solicits re-registration via a `broadcast` envelope on `system.broadcast` with `payload: {action: "request_register"}`. Online agents re-publish their cards within 5 s.

v0.2 replaces this with a JetStream KV bucket (`AGENT_CARDS`).

## 4. Conformance levels

| Level | Requires | Who this is for |
|---|---|---|
| **L1 — Reachable** | Envelope §1, lifecycle §2, Agent Card §3. Can receive `command`, reply with `result`. | ESP32 sensor, shell-script agent, any minimal worker. |
| **L2 — Collaborative** | L1 + handles `delegation`, enforces `hop_count >= 8` refusal, propagates `context_id`. | AG2 agents, LangGraph agents, anything that delegates to peers. |
| **L3 — Typed** | L2 + publishes A2A skill schemas + runs an MCP endpoint. | Agents whose capabilities need to be invoked programmatically by planners. |

An implementation declares its level in `metadata["runtime.conformance"]`. The field is **mandatory** in v0.2+ (`schemas/agent-card.v1.json` enforces it). Adapters that previously shipped without it default to `"L1"` (gemma, hermes, watchdog, shell). The AG2 adapter ships at `"L2"` after Phase 4.2; `mcp-1` and `a2a-gateway` ship at `"L1"`.

## 5. Reference adapters

The contract is only useful if it's cheap to implement. Each reference adapter is a thin wrapper that puts an existing framework behind the contract.

- **shell-adapter** (Task 12) — minimal L1 reference in `nats-py` async. ~200 lines. Runs an arbitrary shell command on each `command`; the stdout becomes `result.body`. Proof that L1 is trivial.
- **openclaw-client** (Task 13) — rewritten in `@nats-io/nats`. Legacy paho-mqtt is deleted, not wrapped.
- **AG2 + A2A wrapper** (Phase 4) — wraps an AG2 `ConversableAgent` with `A2aAgentServer(agent, agent_card=card)`. A bridge process translates between the local A2A HTTP+SSE endpoint and NATS subjects.
- **LangGraph adapter** (post-v0.1, planned) — invokes a LangGraph graph per inbound `command`; emits `task.progress` from node transitions.

Each adapter is small on purpose. If an adapter is more than ~500 lines, the contract is wrong, not the adapter.

## 6. Non-goals (v0.1)

- **Per-agent authentication.** Single shared token for now. Per-agent JWTs come with v0.2.
- **Streaming tokens.** The envelope reserves `agents.{id}.task_progress.{task_id}` but does not define token-level semantics yet.
- **Cross-site federation.** `metadata["runtime.deployment"]` is captured but unused for routing.
- **Durable Agent Card discovery.** v0.1 uses an in-memory aggregator cache + `request_register` broadcast on aggregator restart. JetStream KV for cards is v0.2.
- **A2A HTTP+SSE interop.** The A2A *vocabulary* is adopted in v0.1; the *HTTP binding* lands in Phase 4 via `A2aAgentServer`.

## 8. A2A and MCP surfaces (Phase 4+)

Phase 4 introduces three new surfaces beyond the v0.1 contract. None changes the envelope schema; they extend the runtime vocabulary.

### 8.1 L2 conformance reference

L2 means the agent handles `delegation` envelopes, enforces `hop_count >= 8` refusal, and propagates `context_id` across hops. The reference implementation is the AG2 adapter (`adapters/ag2/`, Phase 4.2). Shared helpers at `adapters/_common/l2_orchestrator.py` provide:

- `publish_delegation(nc, *, recipient, body, sender_id, context_id, parent_task_id, hop_count, skill_id=None)` — emits a `delegation` envelope on `agents.{recipient}.inbox` with the dedup contract.
- `await_result_for_task(consumer, task_id, *, timeout)` — awaits the matching `result` on the sender's inbox.
- `refuse_if_hop_limit(env)` — pre-built rejection envelope when `hop_count >= 8`.
- `propagate_context(inbound_env, *, new_task_id)` — extracts fields a child delegation must echo.

Future framework adapters (LangGraph, CrewAI, Pydantic-AI, Google ADK) reuse these helpers; ADR-0010 locks NATS-native delegation as the in-fleet transport.

### 8.2 MCP exposure

The MCP server at `mcp-server/` (Phase 4.3) speaks the Model Context Protocol over stdio (Claude Desktop / Cursor mounts) and HTTP+SSE (remote clients including Hermes' built-in MCP client and AG2's `MCPToolkit`). It is a first-class fleet subscriber registered as agent `mcp-1` (`runtime.kind: gateway`, `runtime.roles: [orchestrator]`, `runtime.conformance: L1`). Tools surfaced (1:1 with NATS / aggregator primitives): `publish_command`, `list_agents`, `query_messages`, `cancel_task`, `delegate`. Per-caller attribution lives in `payload.metadata.caller`. See ADR-0011.

### 8.3 External A2A ingress

The A2A gateway at `a2a-gateway/` (Phase 4.4) is a slim FastAPI service exposing A2A v1.0 HTTP+SSE endpoints for any agent whose `runtime.roles` overlaps `{reasoner, worker}`. It is registered as agent `a2a-gateway` (`runtime.kind: gateway`). The gateway is purely external-edge — it never participates in in-fleet delegation (ADR-0010). Per-session attribution lives in `payload.metadata.origin_session`.

## Bridge adapters

Adapters with `runtime.kind: bridge` front a third-party agent product that already owns reasoning + memory + tool-calling — Nous Research's Hermes Agent (`us-mac-hermes`, Phase 6) is the reference implementation.

### Required card metadata

- `metadata.runtime.kind: "bridge"`
- `metadata.runtime.upstream`: identifier of the upstream agent product (e.g., `hermes-agent`). The agent-card factory (`adapters/_common/agent_card.py`) refuses to build a card with `kind: bridge` and an empty `upstream`.
- `metadata.runtime.tags`: SHOULD include `external-memory` if the upstream owns memory; this surfaces on the dashboard so operators know not to query `memory.turns.*` for this agent.

### Memory ownership rule

Per [ADR-0009](adr/0009-bridge-adapter-memory-ownership.md):

- **Bridge adapters MUST NOT publish to `memory.turns.{get,put,delete}`.**
- Bridge adapters MAY pass `context_id` to the upstream as an opaque session token (HTTP header, query param, etc.). The upstream is responsible for any continuity semantics that follow.
- The aggregator's envelope ledger (`messages` table, fed by `agents.{id}.{outbox,log,heartbeat,status}`) remains the canonical cross-agent audit record for bridge agents.

### `task.progress.payload.extra.upstream`

Bridge adapters SHOULD include `payload.extra.upstream: <upstream-id>` on every `task.progress` envelope they publish, so consumers (dashboard, future analytics) can attribute streaming activity to the correct upstream product. Hermes' bridge sets `upstream: "hermes-agent"`.

### Onboarding pattern

Local bridge adapters follow the three-step onboarding in [03-agent-registration.md §"Local adapter onboarding"](03-agent-registration.md#local-adapter-onboarding) — install the upstream, get NATS broker info from `add-agent.sh`, configure `agent.env`, run the adapter (or load its launchd plist).
